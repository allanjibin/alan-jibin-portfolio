Real-Time Automated Crack Detection for Interlocked Metal Chains

1. Engineering Architecture & Hardware Components

The proposed system is an integrated mechatronic solution designed for autonomous industrial inspection. At the physical layer, the conveyor system is powered by a high-torque Micro DC Geared Motor. This component is selected for its ability to maintain constant linear velocity, ensuring the frame rate of the image acquisition system remains synchronized with the material throughput.

To ensure precision, speed is governed by a PWM (Pulse Width Modulation) Controller. By manipulating the duty cycle of the motor’s input signal, we regulate velocity without losing the torque necessary to pull the heavy, interlocked metal chains, preventing slippage or jerkiness that could introduce motion blur into the image stream.

Energy delivery is stabilized via a 12V AC-DC SMPS (Switched Mode Power Supply). Unlike linear regulators, this SMPS utilizes high-frequency switching to achieve high efficiency (typically >85%) while significantly reducing the physical size of the power stage. This provides a clean DC rail for the motor drivers and LED lighting, eliminating electrical noise that could degrade the signal-to-noise ratio in the camera feed[cite: 374, 407, 427].

2. System Concept & Logic Sketch

This sketch delineates the spatial constraints of the system. The enclosure is constructed from a rigid aluminum-cardboard composite, which acts as a Faraday cage of sorts, minimizing external EMI (Electro-Magnetic Interference) and ensuring consistent, diffused lighting—a non-negotiable requirement for accurate edge detection. The laptop serves as the central processing unit, running the YOLOv8 inference engine. By placing the Arducam within a fixed-geometry housing, we establish a constant focal distance, meaning the model does not need to handle varying object distances, thus significantly improving the mean Average Precision (mAP) during the inference phase[cite: 396].

3. System Architecture & Flowchart Deep-Dive

The system is logically partitioned into three functional domains. The Data Acquisition Tier operates as the physical sensory layer, transforming mechanical movements into digital signals. The Processing Unit functions as the algorithmic core, where Python 3.11 manages the inference lifecycle. The Output Interface acts as the execution layer—it interprets the binary results ("Safe" vs "Defective") and triggers mechanical or acoustic response modules.

The flowchart depicts the conditional state machine logic. It begins with the initial calibration (loading the .pt weights). The scan loop is an interrupt-driven process; should the model confidence exceed the 0.15 threshold, the global variable chain_is_safe is toggled to false, and the buzzer output is latched. This state-machine design ensures the system handles errors gracefully, maintaining a log of all detections in a CSV file for archival verification[cite: 588].
