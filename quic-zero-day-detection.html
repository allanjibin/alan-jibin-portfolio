Unsupervised Zero-Day Detection in Encrypted QUIC Traffic

Investigating anomaly-based detection for the QUIC transport protocol, where end-to-end encryption blocks the payload-inspection techniques traditional intrusion detection systems rely on.

1. Why QUIC Breaks Traditional IDS

QUIC (the transport protocol underlying HTTP/3) encrypts almost everything above the UDP layer by default, including handshake metadata that older protocols like TCP left exposed. This is great for user privacy, but it strips away the signals that signature-based and deep packet inspection systems have historically relied on to spot malicious traffic. A zero-day attack — one with no known signature to match against — makes this problem worse still, since there's no pattern in any database to look for in the first place.

This project starts from the hierarchical ML approach for UDP-QUIC intrusion detection proposed by Jafari, Shafi, and Lashkari as a base paper, and extends the framing toward a fully unsupervised setting: detecting anomalous behavior in encrypted flow-level metadata (timing, packet size distributions, connection patterns) without requiring labeled attack examples at all.

2. Proposed Approach

The core idea under investigation is an Isolation Forest-based anomaly detector operating purely on statistical flow features extractable without decrypting payloads — packet inter-arrival times, flow duration, byte-count distributions, and connection-establishment patterns. Because it requires no labeled attack data, this approach is designed to generalize to attack types that haven't been seen before, which is the entire point of "zero-day" detection.

Early-stage work has focused on building the seminar and presentation material framing this problem for a SECRYPT audience, situating it against the base paper's supervised hierarchical classifier and identifying where an unsupervised approach offers a genuine advantage — and where it trades away detection precision to get there.

3. Status

This project is in active development. The next phase involves sourcing or generating labeled QUIC traffic captures for evaluation purposes only (not training), building the feature extraction pipeline, and benchmarking the Isolation Forest approach against the supervised baseline from the base paper.
