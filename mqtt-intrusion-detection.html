1. Dataset & Feature Engineering

The pipeline is built on the BCCC-IoT-MQTT-IDS-2025 dataset, a large-scale labeled capture of both benign and attack traffic on the MQTT protocol — the lightweight publish/subscribe messaging standard underlying most IoT device communication. Working from over 6.2 million raw records, the first challenge was scale: the dataset spans roughly 156 GB before reduction, which meant every stage of the pipeline had to be built for memory efficiency rather than convenience, given a development machine without CUDA acceleration.

Stratified sampling was used to preserve the original class distribution while cutting the dataset down to a workable size, ensuring rare attack classes weren't accidentally erased in the process. From there, feature importance was ranked using a one-vs-rest XGBoost approach across each attack category individually, rather than a single global importance score — this matters because a feature that's irrelevant for detecting one attack type can be the single most predictive signal for another. The result was a reduction from hundreds of raw fields down to 138 high-signal features, kept for all downstream models.

2. The Class Imbalance Problem

Like most real-world network traffic, the dataset is heavily skewed: benign traffic and a handful of dominant attack types vastly outnumber rarer attacks like SYN flooding and basic connect flooding. Left untreated, this causes models to effectively ignore minority classes while still posting misleadingly high overall accuracy.

Two balancing strategies were built and compared head-to-head:

Variant 1 — SMOTE Oversampling

Synthetically generated samples for minority classes. Improved raw class representation but led to class collapse on the rarest attack types, where models struggled to generalize from synthetic points.

Variant 2 — Dominant-Class Downsampling

Reduced the size of over-represented classes instead of inflating rare ones. Slightly lower ceiling on overall accuracy, but significantly better detection of minority attack types — the metric that actually matters for a security system.

3. Model Comparison

Six classifiers — Random Forest, XGBoost, Decision Tree, Neural Network, MLP, and Naive Bayes — were trained and evaluated across both balancing variants and three train/test splits (60:40, 70:30, 80:20), producing 36 distinct configurations. Split ratio variation turned out to be largely negligible at this dataset size; the balancing strategy was the dominant factor in outcomes.

Random Forest on the downsampled (v2) variant at an 80:20 split was selected as the recommended deployment model — Gradient Boosting posted a marginally higher raw accuracy (87.74%) but at roughly 3× the training cost (~790s vs. ~273s), making Random Forest the better trade-off for practical deployment.

4. Positioning Against Existing Work

To contextualize the approach, the pipeline was benchmarked conceptually against MQTTFlowLyzer, a recent TabNet-based MQTT intrusion detection system. The comparison highlighted genuine points of differentiation — particularly the per-class feature selection strategy and the explicit downsampling-vs-SMOTE analysis — which form the core contribution of the SECRYPT submission currently in preparation.
